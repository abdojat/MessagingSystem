Build a production-ready web chat app using React + Next.js (App Router) + TypeScript. The backend is already implemented and exposes REST under /v1 (and the same routes also exist without /v1). Use the /v1 base path by default.

Goal: a Telegram-like channel messaging client with authentication, channel discovery, channel membership management (roles), real-time messaging via WebSocket, message history pagination by seq_id, unread/seen state, reactions, pins, invites, uploads, and a sync mechanism.

TECH STACK / PROJECT RULES

Next.js App Router, TypeScript, modern best practices.

Use a clean UI component system (shadcn/ui or similar), Tailwind CSS.

State: React Query (TanStack Query) for REST data fetching/caching. Use a small client-side store (Zustand or context) only where necessary (auth token, websocket connection status, current channel).

Auth tokens stored securely: prefer httpOnly cookies if possible; if not, store in memory + refresh token in localStorage with careful handling. Implement refresh flow.

Must support SSR where useful, but messaging UI can be client components.

Create a configurable environment variable:

NEXT_PUBLIC_API_BASE_URL (example: http://localhost:8000
)

All REST calls go to ${NEXT_PUBLIC_API_BASE_URL}/v1/...

WebSocket connects to ${NEXT_PUBLIC_API_BASE_URL}/v1/ws (convert http->ws, https->wss)

Build a centralized API client with:

access token injection

automatic refresh on 401 (call POST /v1/auth/refresh with refresh_token)

request/response typing

standardized error handling using common error response {code,message,details}

Provide a complete runnable project with folder structure, pages, components, hooks, and minimal styling polish.

BACKEND CONTRACT (USE EXACTLY)
REST endpoints & schemas are as follows (do not invent new endpoints):
Auth:

POST /v1/auth/register (RegisterRequest) -> {id, username, email}

POST /v1/auth/login (LoginRequest) -> TokenPair {access_token, refresh_token, token_type}

POST /v1/auth/refresh (RefreshRequest) -> TokenPair

POST /v1/auth/logout (LogoutRequest) -> {status:"ok"}

GET /v1/auth/sessions -> {items: SessionResponse[]}

POST /v1/auth/logout_all -> LogoutAllResponse

DELETE /v1/auth/sessions/{session_id} -> {status:"ok"}
User:

GET /v1/me -> MeResponse

GET /v1/users/search?q=... -> UserSearchResponse (cursor pagination)

GET /v1/users/{user_id} -> UserPublicProfile
Channels:

POST /v1/channels -> ChannelResponse

GET /v1/channels -> {items: ChannelResponse[], next_cursor, has_more}

GET /v1/channels/{channel_id} -> ChannelResponse

PATCH /v1/channels/{channel_id} -> ChannelResponse

DELETE /v1/channels/{channel_id} -> {status:"ok"}

GET /v1/channels/{channel_id}/my-membership -> {channel_id,user_id,role,...}

GET /v1/channels/{channel_id}/stats -> {channel_id,member_count,pending_count,message_count,last_message_at}
Membership / Invites:

POST /v1/channels/{channel_id}/join (JoinRequest) -> JoinOutcomeResponse

POST /v1/channels/{channel_id}/leave -> {status:"ok"}

GET /v1/channels/{channel_id}/members -> cursor pagination

GET /v1/channels/{channel_id}/requests -> cursor pagination (pending)

POST /v1/channels/{channel_id}/invite (InviteRequest) -> InviteResponse {id,token,channel_id,expires_at}

GET /v1/channels/{channel_id}/invites -> cursor pagination

POST /v1/channels/{channel_id}/invites/{invite_id}/revoke -> {status:"ok"}

GET /v1/invites/{token} -> validity + channel summary + invited targets

POST /v1/invites/{token}/accept -> MembershipActionResponse

POST /v1/channels/{channel_id}/members/{user_id}/approve -> MembershipActionResponse

POST /v1/channels/{channel_id}/members/{user_id}/add -> MembershipActionResponse

POST /v1/channels/{channel_id}/members/{user_id}/promote -> MembershipActionResponse

POST /v1/channels/{channel_id}/members/{user_id}/demote -> MembershipActionResponse

DELETE /v1/channels/{channel_id}/members/{user_id} -> {status:"ok"}
Messages:

POST /v1/channels/{channel_id}/messages (PublishMessageRequest) -> MessageResponse

GET /v1/channels/{channel_id}/messages?before_seq_id=&after_seq_id=&limit=&order=asc|desc -> {items,next_before_seq_id,next_after_seq_id,has_more,order}

GET /v1/channels/{channel_id}/messages/around?seq_id=... -> {seq_id, items: MessageResponse[]}

GET /v1/channels/{channel_id}/messages/{message_id} -> MessageResponse

PATCH /v1/channels/{channel_id}/messages/{message_id} (MessagePatchRequest) -> MessageResponse

DELETE /v1/channels/{channel_id}/messages/{message_id} -> MessageResponse
Seen/Unread:

POST /v1/channels/{channel_id}/seen (SeenRequest) -> SeenResponse
Reactions:

POST /v1/channels/{channel_id}/messages/{message_id}/reactions (ReactionRequest {emoji}) -> ReactionSummaryResponse

DELETE /v1/channels/{channel_id}/messages/{message_id}/reactions/{emoji} -> ReactionSummaryResponse
Pins:

POST /v1/channels/{channel_id}/pins/{message_id} -> 204/empty

DELETE /v1/channels/{channel_id}/pins/{message_id} -> 204/empty

GET /v1/channels/{channel_id}/pins -> {items: MessageResponse[]}
Uploads:

POST /v1/uploads (UploadCreateRequest) -> UploadCreateResponse {file_id, upload_url, method:"PUT", headers, public_url}

PUT /v1/uploads/{file_id}/content -> {file_id, public_url}

GET /v1/uploads/{file_id}/content -> binary
Sync:

POST /v1/sync (SyncRequest) -> SyncResponse {server_time, channel_updates, membership_updates, messages}
Events:

GET /v1/channels/{channel_id}/events -> EventListResponse
Health:

GET /v1/health -> {status:"ok", db, redis, rabbitmq}
WebSocket:

WS /v1/ws

auth via query/header OR first message: {"type":"auth","payload":{"token":"..."}}

server sends event envelopes such as: hello, history, message, membership_update, channel_updated, sync, seen, error
